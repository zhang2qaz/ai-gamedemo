# 双人线上剧本杀 ·《摇摆州》

> 2016 年美国大选之夜，佛罗里达州棕榈滩的海葡萄庄园。2 人联机，电脑当 DM，约 2.5 小时。
> 本页不含剧透，可以放心给玩家看。**`swing-state-bible.md` 是作者 / DM 用的剧本圣经，含全部真相，玩家请勿打开。**

## 怎么开一局

剧本杀走的是自定义服务器 `server.ts` 上的 WebSocket（路径 `/ws-mystery`），所以要用它启动，**`npm run dev`（`next dev`）不带联机，开不了房**。

```bash
npm install
npm run start:mp          # 先 next build，再用 tsx server.ts 启动（默认端口 3000）
# 本地开发（热更新）：DEV_MODE=1 npx tsx server.ts
```

1. 玩家甲打开 `http://<服务器地址>:3000/mystery`，输入昵称，点「创建房间」，拿到 4 位房间号。
2. 把房间号（或带 `?room=房间号` 的链接）发给玩家乙，乙输入昵称加入。首页也有入口卡片。
3. 两人各选一个角色（曼迪 / 伊森），都点「准备好了，开始」。

部署到 Railway 时，`railway.json` 已经是 `npm run build` + `npm start`（即 `tsx server.ts`），不需要额外配置。

建房、加入失败按来源 IP 限流。转发头（`X-Forwarded-For`）客户端可以伪造，所以默认只认 TCP 对端地址；Railway 上会自动信任它的代理。如果你部署在别的反向代理（Nginx 等）后面，请设置环境变量 `TRUST_PROXY=1`（取 `X-Forwarded-For` 最右一跳，即代理追加的地址），否则所有玩家会被当成同一个 IP；只有当代理会覆盖写入 `X-Real-IP` 时才用 `TRUST_PROXY=real-ip`。

## 电脑 DM 做什么

- **推进流程**：每个环节都有倒计时；两人都点「继续 / 读完了 / 结束搜证 / 讨论完毕」就提前进入下一环节，时间到了也会自动推进。
- **保管秘密**：每个人只收到自己能看的剧本、线索和私聊结果。对方的手牌、暗标、私下递交的推理和现金余额，服务器都不会发给你；搜查点在报文里也只是一串随机编号；对方搜了你够不着的地方（专属点、还没解锁的点），你只会知道他去了哪个地点。记录按每个人各自编号，对方的视图没变化时也不会给你推送，所以从报文的编号或推送次数里也看不出对方做了什么私密操作。剧情文字只在服务器上，前端代码里没有任何人名与真相（有测试把关）。
- **裁定**：搜证扣行动点、NPC 问话、案卷判分、拍卖结算、终局每轮的结算与结局，全部由服务器按规则判定。
- **掉线恢复**：断线后刷新页面或重新打开，会凭本机保存的身份自动回到原座位，进度不丢。同一身份在另一个窗口登录时，旧窗口会被顶下线。服务器每 30 秒检测一次连接，手机休眠、切网后的"假在线"会被及时识别。
- **离开房间**：在大厅里离开会让出座位，别人可以补位（大厅里掉线超过 1 分钟的座位也可以被补上）；开局后离开，座位会保留，之后在本设备打开本页，入口处会出现「回到房间」；点「放弃这局」会通知服务器（大厅里让出座位，开局后告诉对方你不会再回来了），断网时点的离开 / 放弃会在连上后自动补发。暂离着一局时直接创建或加入别的房间，成功进入新房间后等同于放弃那一局（搭档会收到通知；加入失败则什么都不放弃）。同一设备开了第二个窗口时，旧窗口会被顶下线，入口页可以「在此窗口继续」（同一台设备只能记住一局，所以这时不能在旧窗口里另开新局）。
- **防误操作**：与阶段绑定的操作（准备、搜证、出价、下令等）带着当时的阶段编号，双击或网络迟到的操作不会落到下一阶段；公开、交出线索、递交案卷跨阶段都有效，不受影响。离线时点的按钮不会被缓存补发，会直接提示"没有发出"。

## 一局的流程

| 环节 | 时长 | 你要做的事 |
|---|---|---|
| 序幕 · 大选之夜 | 5 分钟 | 了解背景 |
| 第一幕 · 八方豪宴 | 15 分钟 | 读自己的剧本 |
| 自我介绍 | 7 分钟 | 用语音或文字向对方介绍自己（可以隐瞒） |
| 21:30 · 慈善拍卖 | 7 分钟 | 用现金暗标竞拍四件道具，它们会在终局派上用场 |
| 第二幕 · 两点四十分 | 15 分钟 | 继续读剧本 |
| 噩耗 | 5 分钟 | — |
| 搜证一 · 03:20 | 18 分钟 | 8 点行动点：搜现场、问 NPC，决定公开、私藏还是转交线索；可以私下递交「案卷」换酬金 |
| 交锋一 | 12 分钟 | 互相盘问 |
| 第三幕 · 04:15 | 10 分钟 | 新的剧本与线索 |
| 搜证二 · 04:30 | 15 分钟 | 6 点行动点 |
| 交锋二 | 12 分钟 | 互相盘问 |
| 盘凶 · 向 DM 交底 | 20 分钟 | 回答 7 道题，每答对一题得分并领酬金（超时未交视为放弃作答） |
| 终局 · 黎明计票 | 约 20 分钟 | 三轮「证据即选票」的大机制，中途会有人来找你谈交易 |
| 06:00 · 破晓之前 | — | 结局、计分、真相复盘 |

进入终局后，页面上的「📖 规则」可以随时展开，查看完整规则。

## 代码在哪

| 路径 | 内容 |
|---|---|
| `app/mystery/` | 页面入口与样式 |
| `components/mystery/` | 客户端界面（大厅、剧本、搜证、拍卖、终局、结局） |
| `store/mysteryStore.ts`、`lib/mystery/client.ts` | 客户端状态与联机（自动重连、断线恢复） |
| `lib/mystery/hub.ts`、`lib/mystery/protocol.ts` | 服务端多房间中枢与消息协议 |
| `engine/mystery/core.ts` | 通用剧本杀引擎（纯函数，即 DM） |
| `engine/mystery/scenarios/swing-state/` | 《摇摆州》剧本内容与终局机制（**含剧透，只在服务端加载**） |
| `engine/mystery/scenarios/meta.ts` | 无剧透的标题与简介，客户端只允许引用这一个剧本文件 |

## 验证

```bash
npx jest engine/mystery lib/mystery                       # 引擎、剧本逻辑（唯一解等）、整局流程、终局机制、联机中枢、浏览器端连接、前端防剧透

npx tsx scripts/mystery-bots.ts ws://127.0.0.1:3000/ws-mystery   # 先启动服务器；两个机器人联机打完整局
```
